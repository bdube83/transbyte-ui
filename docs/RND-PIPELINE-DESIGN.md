# Edgebox admin R&D pipeline — design

Goal: an internal R&D board where the owner tracks business experiments (hypotheses) toward the
R100M/month goal from `docs/edgebox-revenue/START-HERE.md`, reachable now without Google sign-in.

Decision (2026-09-16): add native email/password + TOTP admin auth so `info@Khuselaworkflow.com`
can reach the internal area without Google (which is not enabled yet, issue #7). One admin login
unlocks both the existing Commercial workspace and the new R&D board.

## Auth (email/password + TOTP, Khusela-style)
- Credential in env only: `EDGEBOX_ADMIN_EMAIL`, `EDGEBOX_ADMIN_PASSWORD_HASH` (`saltHex:hashHex`,
  scrypt-64), `EDGEBOX_ADMIN_TOTP_SECRET` (base32). Generated by `scripts/admin-cred.mjs`, never
  committed. Single owner-admin; no signup surface.
- `POST /api/v1/admin/login {email,password,otp}`: constant-time email + scrypt password + RFC 6238
  TOTP (30s, +-1 window), all evaluated before the verdict. Rate-limited per email, per IP, global.
  On success mints `admin-sessions/<digest(token)>` and a `__Host-eb-admin` cookie
  (Secure, HttpOnly, SameSite=Strict, 2h) with its own CSRF token.
- `adminAuth(req)`: valid `__Host-eb-admin` session, or a Google customer session that passes
  `isInternal` (sub allowlist). 401 when unauthenticated, 403 when authenticated but not internal.
- `GET /api/v1/admin/session` returns `{admin, operator:{id,email}, csrf}` for whichever path is valid.
  `commercial.ts` `commercialAccess` now probes this single endpoint, so the MFA admin unlocks the
  Commercial workspace too (previously it required Google via `/auth/session` + `/admin/orgs`).

## R&D board
- Stages: idea, designed, running, measured, decided.
- Experiment: `{id, title, hypothesis, cheapest_test, cost_minor, gate, stage, result, decision}`.
  Decision in `'' | pursue | kill | iterate`. Gate in `r100k | r1m | r10m | r100m`.
- One CAS blob `rnd/board = {experiments[], current_mrr_minor, note, updatedAt}` (<=500 experiments).
- Revenue gates fixed from START-HERE: R100k, R1M, R10M, R100M (in ZAR minor). `current_mrr_minor`
  is edited by hand; the UI marks the next gate and the gap.
- Endpoints (all `adminAuth` + CSRF on writes): `GET /admin/rnd`, `POST /admin/rnd/experiments`,
  `POST /admin/rnd/experiments/:id` (patch), `.../delete`, `POST /admin/rnd/gates`.

## Frontend
- `/admin` route (`AdminApp.jsx`): email/password/OTP login, then the gate header + a five-column
  board with per-card stage/decision selects, result field, delete, and an add-experiment form.
- `CommercialApp` bootstraps via `/admin/session` and its signed-out state links to `/admin`.

## Security notes
- Password scrypt-64, TOTP RFC 6238, constant-time compares throughout. Secrets only in env; the
  generator prints them to the operator's terminal, never to git or an issue.
- Admin session separate cookie, SameSite=Strict, 2h, server-side revocable via logout.
- Login rate-limited per email/IP/global. R&D data is owner-only, no customer data mixed.

## Known limitations
- Single admin identity. No multi-admin, no password reset flow (regenerate the env hash to rotate).
- Manual MRR entry (no billing integration; billing is a separate future item).
- Reaching the admin needs the three env vars set on Netlify (human action).
- The R&D board is a manual tracker, not the AI idea-engine variant sketched for Khusela.
